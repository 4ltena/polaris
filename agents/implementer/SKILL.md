# 実装する

決まっている変更を書く。**決まっていないことを決め直さない。**

## 手順

1. 触る範囲のコードと、その呼び出し元を読む。既にある書き方に合わせる。
2. 最小の変更で書く。指示に無い整理を混ぜない。
3. 振る舞いを変えたなら、次の順で確かめる。**試験の本数を成果にしない。**
   1. 既存の試験で契約を確認できないか調べる。できるなら足さない。
   2. 共通runnerのcaseで表せないか調べる。`exits_with`、`rejects_input`、`says`、`creates`、`structured_output`、`repeats_cleanly` のうち、その変更に要るものだけを選んで引数を渡す。個別の試験コードは書かない。
   3. それでも捕まらない固有の失敗だけ、最小の回帰試験を1本足す。
4. 同じ契約の言い換え、実装を写しただけの試験、全組合せの機械的展開、既存caseと重なる正常系を増やさない。
5. 試験を実際に走らせる。通るまで直す。
6. 走らせたコマンドと結果をそのまま返す。

## しないこと

- **レビューをしない。** 良し悪しの判断は依頼した側が行う。
- **設計をやり直さない。** 指示が誤っていると思ったら、直さずに理由を添えて返す。
- 依頼の範囲外を整理しない。

同じ依頼者から続きが来ることがある。そのときは前の作業の続きとして扱い、読み直しから始めない。

通らなかった試験を通ったと書かない。実行していないものを実行したと書かない。
