# 文書を書く

三層ある。**書く前に決めること**、**読み手が動けるように並べること**、**文をどう書くか**である。層が衝突したときの優先順位は最後の節に書いた。

## 一　書く前に決める

**直すのは下書きではなく前提である。** 出力が「そう言いたいんじゃない」になるのは腕のせいではない。書かれていない制約を、モデルが「最も平均的な場合」で埋めるからである。そこを直さずに文面をいじると、5分で出た草稿を1時間かけて捨てることになる。

| 前提 | 中身 |
| --- | --- |
| 目的 | 読み手に**取ってほしい行動**。「理解してもらう」ではなく「次回の日程を押さえる」 |
| 読み手 | 役割と、その人が置かれている状況。**最終的に決める人を1人に名指す** |
| 段階 | 初回接触か、関心を得たあとの実務か、承認直前か |
| 使い方 | 雛形として使い回すのか、この1回限りか。共通部と個別部を分ける |
| 素材の条件 | 出してよい情報の境界。許諾のない社名、伏せる数字、明かせない事情 |

段階を書かないと、何を書いても自己紹介の資料になる。

「やらないこと」も3つ書き出す。**範囲**（どこまで自分が持つか）、**触らない領域**（構成だけ、あるいは体裁だけ。両方を一度に動かさない）、**決めない数字**（「枚数は指定しない。筋書きに合わせる」）。能力を縛っているのではない。往復を減らしているだけである。

「まず分割しましょう」「会社概要から始めましょう」と返ってきたら、それは提案ではなく**前提が足りていない合図**である。出力に手を入れず、入力の前提を差し替える。

外に出す文書を最後まで一気に作らない。**本文の段階で食い違っていれば、あとは全部作り直しになる。**

## 二　読み手が動ける順に並べる

一で決めた目的は**取ってほしい行動**である。並べ方はそこから決まる——その行動が最初に来る。

### 行動を求める文書か、論じる文書か

**この選択が並べ方を決める。** 手順書、案内、報告、依頼は前者。設計の根拠、比較、解説は後者。

**行動を求める文書**では、

- 冒頭に読み手ができることを置く。前置きでも計画でもなく、行動を。コマンド・パス・断片があるならそれが先で、説明は後、あるいは無し。
- 手順が2つ以上あるなら番号を振る。1項目1動作で、「そして」が二度入る項目を作らない。**要らない手順は削り、些細なものは前へたたむ**——完走される短い道のほうが、放棄される完全な道より良い。
- 未了があるなら、**次にやる1つ**を名指して終える。
- いまどこにいるかを書く。「3/5完了：schemaを更新した。次は新しい列の埋め戻し」。読み手が前回の位置を覚えている前提を置かない。
- 見積もりは具体的な単位で書く。「試験が既にあるなら15分ほど。無ければ半日」。**分からないなら「分からない」と書く。「少し手間」は最も役に立たない。**
- 済んだことは、いま何が動くかで示す。「magic linkでログインできる。`npm run dev` して `/login`」。

**論じる文書**では、段落は1トピック、冒頭で前段との論理関係を接続表現で示し、論証は一方向に進め、反論を処理したあとに結論を一度だけ置く。**山場で効かせたい情報を手前で先出ししない。**

### どちらの文書でも

- **脱線を分ける。** 2件目があるなら1件目を終えてから、別の問いとして出す。書いている途中で湧いた疑問は脱線ではない——自分で答えられるなら答えて畳み、それでも読み手が要るなら最後に一度だけ出す。
- **一覧は1組5件まで。** 多いときはまとめて、関係の深いものから並べる。**これは見せ方の規則であって、調査・検索・候補生成・保持する情報を削る理由にはならない。** 完全さが要る場面で落とさない。
- **前置きと結びを置かない。** 「まず〜について説明します」「ご不明な点があれば」。答えから始め、答えが終わったら終える。
- **失敗は淡々と書く。** 「うまくいっていないようです」ではなく、原因と直し方を。「`auth.spec.ts:42` で200のはずが401。原因はヘッダの欠落。`Authorization: Bearer ${token}` を足す」。

## 三　文をどう書くか

以下は日本語技術文書の規範である（[k16shikano](https://gist.github.com/k16shikano/fd287c3133457c4fd8f5601d34aa817d)、Unlicense）。

**論証の厳密さ** — 推量や可能性を、根拠なく断定に変えない。異なるものを「同じ」とまとめない。複数の要因がある事象を単一の原因に還元しない。因果を主張するなら、その機構を一文で示す。挙げた例が主張を実際に支えているか確かめる。否定・限定するときは、否定する命題を「」で正確に書き出す。

**読み手の負荷** — 一度に増やす情報は一段だけ。あとで参照しない固有名を出さない。新しい概念は、種類と地位を先に示す。節の問いと帰結に関係しない詳細だけを省く。

**視点と語り** — 行為者を主語にした動作の連なりで書く。読者を「あなた」と呼ばず役割名を使う。術語は分野の慣用語を選び、非術語の場面へ流用しない。イ形容詞の終止形に「です」を続けない。

**演出の抑制** — 溜めや修辞疑問は議論に効く要所だけ。太字は誤読を防ぐときと節の帰結だけ、**一節に一、二箇所**。命令調より「するわけにはいかない」の形。「重要なのは」と予告しない。

**使わない型** — 予告と総括（「本章では〜を扱う」「要するに」）、正面から系（「正面から扱う」）、空虚な形容（「不可欠」「多角的」）、空虚な動詞（「掘り下げる」「触れる」）、接続の型（「においては」、「さらに」の連打）。

**翻訳調と擬人化** — 英語慣用句の直訳を避ける（「運ぶ」「開かれた問い」「住んでいる」）。無生物主語の構文は人か処理の主体へ戻す。話し言葉の評語（「効く」「刺さる」「筋がいい」）を書き言葉で使わない。

**冗長** — 同じ主張を言い換えて繰り返さない。場面を描いた直後に要約し直さない。並列する事実は一文にまとめる。想像上の読者との問答を修辞に使わない。

**見出し** — 作業手順ではなく、答える問いか扱う対象を指す。結論を見出しにしない。疑問形か名詞句かは本文のトーンで選ぶ。

## 四　層が衝突したら

三層は独立ではない。ぶつかる箇所は決まっていて、決着も決まっている。

| 争点 | 決着 |
| --- | --- |
| 状態の書き直しと「予告の禁止」 | **別物である。** 「いま3/5、次は埋め戻し」は状態。「本章では〜を扱う」は中身のない宣言。前者は残し、後者は消す |
| 番号と「見出しは問いを指す」 | **順序が情報であるときだけ番号を振る。** 手順でない並びに番号を振ると、無い順序があるように見える |
| 成果を目立たせることと太字の上限 | **密度は規範が勝つ。** 目立たせるのは太字ではなく**位置**——先に置く |
| 具体的な見積もりと「推量を断定にしない」 | 具体値を出すか、**分からないと書く**。「少し手間」は両方に反する |
| 冒頭に行動と「山場を先出ししない」 | **文書の種類で分かれる。**（二の冒頭） |

## 送る前に消すもの

1. これから何をするかを告げているだけの最初の一文。
2. 「ほかにありますか」と訊く、あるいは済んだことを繰り返す最後の一文。
3. 「ちなみに」の横道。
4. 情報を持たない緩衝語（「おそらく」「かもしれない」）。**本当の不確かさを運ぶ緩衝語は残す**——消すと、無い確信を作ることになる。
5. 比喩と慣用句。字義どおりの動作へ置き換える。

そのうえで確かめる。**最初の一行と最後の一行だけを読んだ読み手が、次に何をするかと、いま何が済んだかを分かるか。**
