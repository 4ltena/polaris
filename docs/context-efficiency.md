# コンテキストの効率化とローカル記憶

Polarisの使用量は、通常の応答に加え、履歴要約と子エージェントの応答を含む。応答にusageがない場合や要求が失敗した場合は、確認済みの合計と欠測件数を区別する。キャッシュ分は入力の内数であり、合計へ再加算しない。固定プロンプトの短縮率や通信量の削減率を、そのまま総消費量の削減率として扱わない。

## 圧縮と履歴保存

```
polaris --remember --compact-at 60000
```

`--compact-at`は圧縮開始の推定トークン数で、最小値は1,000、既定値は従来どおり200,000。上の60,000は比較用の例であり、推奨最適値ではない。利用するモデルの入力・出力上限に合わせて選ぶ。通常は直近2ユーザーターンを保持する。単一ユーザーターンでツール往復が続く場合は、元の依頼、直近2組の完了済みツール往復、未完了の呼び出しを保持して、それ以前を圧縮する。安全に分割できない履歴は変更しない。

要約が短くならなければ履歴を置換しない。自動圧縮が失敗した場合は、履歴が前回比10%または1,000推定トークンの大きい方だけ増えるまで再試行を抑える。手動圧縮はこの抑止の対象外。

`--remember`を指定すると、圧縮前の全Messageを、再開用ログとは別のローカルアーカイブへ保存する。保存できなければ履歴を置換しない。通常の実行は過去の対話を一括取り込みせず、圧縮されない短い会話も自動的には索引へ保存しない。

検索用本文は最大2,000文字の断片に分け、発話者、プロジェクト、セッション、アーカイブと文字範囲を保持する。記録時刻はアーカイブ時刻であり、出来事の発生日時ではない。暗号化されたreasoningは原文保管にのみ残し、検索や埋め込みの対象にしない。アーカイブには元の会話やツール結果が含まれるため、有効化は保存したい会話に限る。

## 検索

```
polaris memory search "前に決めた色"
polaris memory get SESSION_ID RECORD_ID
polaris memory get SESSION_ID RECORD_ID --start 0 --max-bytes 512
```

検索は現在のプロジェクトに限定される。別の対象を明示する場合は`memory --project PATH`を使う。検索結果は既定5件、各抜粋512バイトまで。本文の取得は別の`get`で行う。検索は現在の会話へ自動投入しない。モデルへ渡す場合も過去の引用として扱い、現在の指示、承認、最新のコード状態として扱わない。

抜粋は検索語がまとまって現れる箇所を優先する。検索順位が同じ候補では記録時刻を比較するが、異なる日時形式を横断した時刻の正規化は行わない。`get`の範囲指定はUTF-8バイト単位で、文字の途中を開始位置にできない。範囲取得の既定は512バイト、上限4,096バイト。返された`range.end`から続きを取得できる。範囲指定がなければ従来どおり全文を返す。

初期のキーワード検索はUnicode文字列の部分一致であり、日本語の句やコード識別子を検索できる。形態素解析やBM25ではない。SQLiteへベクトルを保存し、同じモデル・次元のベクトルだけを対象に正確なコサイン類似度で検索する。近似索引は未導入。ハイブリッド検索はキーワードと意味検索の候補順位をRRFで統合する。

## 意味検索を有効にする

OpenAI互換の埋め込みAPIを持つローカルサーバーを別途用意し、モデルを明示する。

```
polaris memory index SESSION_ID --embedding-url http://127.0.0.1:8080/v1/embeddings --embedding-model MODEL
polaris memory search "以前の配色判断" --embedding-url http://127.0.0.1:8080/v1/embeddings --embedding-model MODEL
```

`index`は指定セッションの保存本文、`search`は検索文をローカルサーバーへ送る。外部ホスト、プロキシ、HTTPリダイレクトは使用しない。ローカルサーバー自身が外部転送しないことは、そのサーバーの設定で管理する。埋め込みは圧縮処理から分離し、失敗時に再実行できる。モデル変更時は再索引する。埋め込み要求は通常応答のusage合計には含まれず、別の評価対象となる。

現在の実装は明示的な索引作成であり、埋め込みモデルの自動取得や常駐ジョブは作成しない。意味検索が有効でも、一致するモデル・次元の索引がなければ意味検索由来の候補は得られない。

## 削除と明示取り込み

```
polaris memory forget SESSION_ID
```

この操作は指定プロジェクトの記憶本文、ベクトル、管理下の原文アーカイブを削除し、同じセッションIDの再取り込みを拒否する。通常の再開用会話ログや、利用者が指定した取り込み元ファイルは別物であり、このコマンドでは削除しない。削除済みの会話を記憶へ再登録せず、新しい会話を開始する。

`polaris memory import FILE`は明示したJSONLのみ取り込む。各行に`project_id`、`session_id`、`id`、`role`、`timestamp`、`source`、`text`を持つ記録を置く。`project_id`は対象プロジェクトの正規化された絶対パスと一致させる。元ログを修復するAPIは検索に使用しない。

## 比較手順

同じモデル、推論設定、リポジトリ状態、タスク、受入条件で次を比較する。

1. 既定の圧縮設定。
2. 圧縮閾値を変更した設定。
3. 圧縮と検索を組み合わせた設定。

開始・終了地点を揃え、通常応答、要約、子実行、再試行、埋め込み処理の範囲を記録する。総入力、キャッシュ内外、出力、欠測、往復数、経過時間、正答・手戻りを別々に報告する。少数の一回実行だけで因果や最適値を断定しない。

検索評価には日本語、ファイル名、決定理由、変更済みの決定、存在しない情報、他プロジェクト、削除済み記録を含める。検索を追加した後の総消費量と品質が改善するまで、自動検索や専用ベクトルDBサーバーを必須化しない。

## GPT-6 mediumの測定

`--model gpt-6-astra --effort medium`でモデルと推論設定を固定できる。既定モデルは変更していない。

`POLARIS_METRICS_PATH`を指定すると、CodexプロバイダーのHTTP要求ごとに使用量、成否、時間、モデル、推論設定、要求の指紋をJSONLへ記録する。再認証による再試行も別の要求として記録する。会話本文、認証情報、パス、暗号化reasoningは記録しない。指紋は内容の一致を調べるためのもので、匿名化を保証する暗号学的ハッシュではない。既存ファイルは通常ファイルかつ権限0600が必要。対応OSはmacOSとLinux。

`prefix`は指示とツール、`visible_history_items`は暗号化reasoning以外の各入力項目の指紋とバイト数を持つ。要求間で一致する先頭部分を調べられるが、バイト数をトークン数とみなしてはいけない。欠測はnullであり、ゼロ消費ではない。キャッシュ書き込み量はサービスが返した場合だけ記録する。

比較用スクリプトは合成した3課題（要件抽出、送料計算修正、長い履歴からの決定抽出）を各3回実行する。

```sh
cargo build -p polaris-cli
python3 scripts/benchmark_efficiency.py \
  --binary target/debug/polaris \
  --output /tmp/polaris-gpt6-default-run --label candidate-default
```

出力先には未作成のディレクトリを指定する。各試行は専用`.polaris`を持つ固定パスの作業領域で実行し、終了後のファイル、応答、監査ログ、要求別ログを保存する。次の試行では同じパスに初期ファイルを作り直す。修正課題の指定外変更は不合格。品質判定と計測完全性を別々に記録し、失敗・欠測・モデル不一致・要求別合計の不一致では停止する。修正課題の判定は安全な構文の限定リストを用いるため、別の正しい実装を不合格とする場合があり、結果の目視確認も必要。

CLIの応答・欠測・失敗件数も要求別ログと照合する。キャッシュ読み取り量と書き込み量の完全性は別項目であり、書き込み量が不明なら`cost_comparison_ready=false`として費用比較を未確認にする。

旧バイナリには`--allow-legacy-metrics`を追加できる。この場合、要求別ログがない結果も収集するが、`measurement_complete=false`のままであり、完全性を確認した比較とは扱わない。同一課題の反復には同じキャッシュ用名前空間を指定するが、これはルーティングのヒントであり、初回のキャッシュ未使用や他実行からの隔離を保証しない。

実験条件は次の引数で一つずつ変更する。

|引数|実験内容|
|---|---|
|`--read-output-bytes 8192`|readの出力上限を8KiBにする。未指定時の既存動作を維持する。巨大な単一行の途中で切れた場合は明示し、残りは範囲を絞った別の読み取りで取得する。|
|`--cache-mode explicit`|GPT-6向けの明示的なキャッシュ境界を直近4箇所まで指定する。|
|`--cache-mode implicit`|暗黙的キャッシュを明示指定する。未指定時は従来の要求形式を維持する。|

キャッシュ実験は[OpenAIのPrompt caching仕様](https://developers.openai.com/api/docs/guides/prompt-caching)を基に実装した。2026-09-06のChatGPT認証経路では`prompt_cache_options`がHTTP 400 Unsupported parameterで拒否された。この経路では上記のcache-modeを指定せず、別モデルや別モードへの自動切替も行わない。

files.mdの自動更新はモデル応答内の変更をまとめて重複を除き、必要な読み取り・実行前または次のモデル要求前に反映する。親ディレクトリへの展開後も、更新対象は1回32件までに制限する。上限超過は監査ログに記録する。

`POLARIS_CACHE_PREFIX=stable`は、`gpt-6-astra`のtools付き要求へ固定ガイドを追加する別の実験設定。未指定または`compact`では既存の送信形式を維持する。既定構成の990参照トークンという予算とは別に、stableは621参照トークンを追加する。入力増加がキャッシュ再利用による費用減少を上回る場合もあるため、[キャッシュ率・費用比較](gpt6-cache-cost-results.md)を確認して選ぶ。`POLARIS_CACHE_MODE`との併用は今回の測定対象外。

開発環境では接続が拒否されたが、2026-09-06に利用者のローカル実行を確認した。[初回実測](gpt6-efficiency-results.md)では既定改良版の削減を確認できず、8KiB制限は悪化、明示キャッシュは未対応であった。これらの実験設定は既定採用しない。


依頼文の比較には`--strategy default|scoped|search-first`を使う。`default`は元の依頼文を維持し、`scoped`は合成作業領域の資料と非Git状態、Python検証方法を明示する。`search-first`はそれに長い調査の検索優先を加える。モデルへの追加情報と追加トークンを含めた比較であり、製品側の既定指示を変更するものではない。実行した依頼文はmetadata.jsonへ保存する。

## 大きなツール結果の保存と再取得

```sh
polaris --model gpt-6-astra --effort medium --tool-memory history
polaris --model gpt-6-astra --effort medium --tool-memory retrieval
```

`--tool-memory`は既定`off`。`history`は直近2組の完了済みツール往復を保持し、それ以前の8KiB以上のread・bash結果を保存して短い参照へ置換する。`retrieval`は完了した大きな結果を初回送信前から参照と小抜粋へ置換する。指示、ツール呼び出しID、未完了の呼び出しは変更しない。保存に失敗すれば結果の全文を維持する。`--remember`による圧縮前アーカイブとは独立した設定である。

保存する原文は、ツールが返した時点の結果本文。実行後にファイルが変わっても復元できる。ただし、readやbashの既存出力上限で既に切られた部分まで保存する機能ではない。原文と検索用断片は、既存SQLite記憶ストアにプロジェクト・記憶セッション別で保存する。内容と呼び出し由来のハッシュをIDに使い、暗号化reasoningを索引へ送らない。保存には端末内のディスク容量を使う。

モデルには既存のreadツールで使える参照を返す。ツール総数は6個のまま。

|readのpath|動作|
|---|---|
|`memory://ID`|保存した結果を取得。offsetとlimitは通常のreadと同じ行単位。|
|`memory://ID/search/検索語`|指定した保存結果だけをキーワード検索する。IDが不正・参照不可ならエラーになり、他の結果へ検索を広げない。|
|`memory://search/検索語`|同じ記憶セッションの保存断片を検索し、根拠の抜粋と原文の取得先を返す。|
|`memory://ID/bytes/開始位置`|長い1行を含む原文の続きをUTF-8バイト位置から取得。返された継続URIを使う。|

検索抜粋は行・段落の境界を優先し、同じ原文の離れた一致箇所を最大3箇所返す。近接・重複した範囲は統合する。候補が多い場合は先頭2箇所と最後の箇所を選ぶため、すべての訂正を網羅する保証はない。保存本文の行範囲とバイト位置の取得URIを示す。長い単一行はUTF-8境界で切り、抜粋であることを明示する。

検索・取得の返却量は最大4KiBに制限する。検索結果の参照から必要範囲を取得するための上限であり、全資料を4KiBずつ順に読み直すことを推奨するものではない。抜粋を完全な根拠とみなさず、必要に応じて周辺の文脈を取得する。

記録限定検索は保存時点の結果を探す。現在のファイル内容を確認する場合は通常のパスを読む。記録限定検索では埋め込みAPIを呼ばず、空白区切りの全検索語を含む保存結果から抜粋を返す。全記憶から探す場合は`memory://search/検索語`を使う。

起動時の環境情報が`filemap=ready`の場合だけ、基本プロンプトは探索前に`docs/filemap.md`を読むよう案内する。存在しない場合は`absent`、通常ファイルとして確認できない場合は`unavailable`。これは起動時の状態であり、後から作成・削除されたファイルの状態を保証しない。filemapとその親ディレクトリのシンボリックリンクは辿らない。

意味検索にはローカル埋め込みAPIとモデルを明示する。

```sh
polaris --model gpt-6-astra --effort medium --tool-memory retrieval \
  --tool-memory-embedding-url http://127.0.0.1:8080/v1/embeddings \
  --tool-memory-embedding-model MODEL
```

このURLとモデルは利用者が稼働させたものを指定する。未指定時はキーワード検索のみであり、意味検索として扱わない。設定時は保存断片を埋め込み、問い合わせにも同じモデルを使って意味検索とキーワード検索を組み合わせる。外部ホストやリダイレクトは利用しない。失敗時のフォールバックは結果に明示する。埋め込み要求は本文を含まない専用の計測行を標準エラーへ出し、トークンが返らない場合は欠測とする。

埋め込みが欠けた断片は同じ結果の再保存時に再試行する。検索時の自動再索引は行わない。既存記録の補完には、既存の`polaris memory index SESSION_ID`へ埋め込み設定を指定する。実際の埋め込みAPIとの接続と総トークン削減率は未検証である。

ローカル埋め込みサーバーへの送信は、そのサーバーが外部へ転送しない保証ではない。保存対象の内容を送ってよいサーバーを指定する。LLM要約や埋め込みモデルの自動ダウンロードは行わない。

一発実行では標準エラーに記憶セッションIDを表示する。原文とベクトルの削除は、対象プロジェクトから既存の`polaris memory forget SESSION_ID`で行う。削除済みセッションへ再保存しない。

TUIの同一プロジェクト内のforkは、以前の結果を祖先の記憶から参照し、新しい結果を分岐先自身の記憶セッションへ保存する。再開時は分岐元の出自をたどり、同一プロジェクトで循環がないことを確認する。分岐先のforgetは分岐先の記録を削除し、祖先の記録を削除しない。祖先の記憶が削除済みの場合は、依存する分岐先で記憶の取得・追加保存を停止する。別プロジェクトの記憶を分岐経由で取得することはできない。

### 比較用の長期参照課題

```sh
python3 scripts/benchmark_tool_memory.py \
  --binary target/debug/polaris --output /tmp/polaris-memory-history \
  --label history --tool-memory history --repeats 3
```

新しい出力先を使い、`off`・`history`・`retrieval`を同じバイナリで比較する。3つの大きな資料を順にたどった後、最初の資料の承認済み決定を尋ねる。別台帳と未承認提案を正答に含めない。結果には通常の使用量・品質に加え、`exercise.json`へ保存と記憶readの回数を記録する。機能が実際に使われたかも確認し、単にフラグを指定しただけで効果を判定しない。埋め込み使用量はGPT-6の使用量と区別し、既知分の合計と欠測を併記する。

#### 隔離実行との互換設定

隔離された実行では、状態とセッションだけを専用領域へ分離できる。`POLARIS_DATA_DIR`には空でない絶対パスを指定する。指定時の保存先は`<POLARIS_DATA_DIR>/state/<project-id>`と`<POLARIS_DATA_DIR>/sessions`であり、`HOME`と認証情報の保存先は変更しない。未指定時は従来どおり`~/.polaris/state/<project-id>`と`~/.polaris/sessions`を使う。空文字列や相対パスは既定の保存先へ戻さず、起動前にエラーにする。

`POLARIS_AUTH_READ_ONLY=1`は既存認証を更新しない実行を指定する。未指定または`0`は通常の認証動作を維持する。これ以外の値は不正な設定として停止する。`SSL_CERT_FILE`はmanaged proxyが渡す追加の信頼ルートにだけ使う。指定したbundleが欠落または不正なら通信前に停止し、証明書またはホスト名の検証を無効化しない。

brokerを使うbounded runnerは任意の実測用構成であり、通常のPolaris起動、既定のsandbox、既定の認証動作を変更しない。runnerは許可済みのバイナリ、fixture、実行modeだけをmanifestで固定し、それ以外のprogram、root、引数形は拒否する。brokerが利用できない場合に通常実行へ戻さない。

GPT-6 mediumとretrievalを固定し、単一ファイル修正、複数ファイル修正、長いログの原因特定、承認決定の訂正、過去資料と現行資料の照合を比較する。比較元と候補の実行順を交代し、各3回で30試行。`--repeats 5`なら50試行、`--dry-run`なら推論せず実行予定だけを表示する。修正課題は限定したPython構文で計算結果を検査し、生成コードをホストで無制限に実行しない。

各試行の品質・変更範囲・モデルとeffort・要求別使用量・保存数・記憶read回数を記録する。品質不合格や計測不完全では停止し、成功分だけで改善率を主張しない。総トークンにはキャッシュ済み入力も含める。

過去資料と現行資料の課題では、プロセス起動前にハーネスが現行資料を変更する。過去資料はfixtureであり、実際のmemory保存後に資料を変更した対話や、その再開の実モデル測定ではない。保存後の変更・再オープン・forkとresumeの出自境界は別のオフライン回帰テストで検査する。

2026-09-07に隔離互換版の30試行が完了し、品質・範囲・使用量を再検証した。候補のキャッシュ率は4.0%から11.9%へ増えたが、総トークンも6.5%増加したため、既定offを維持する。両条件とも記憶の再読込は0件で、長期記憶の効果は未検証。[課題別の結果と制約](gpt6-efficiency-results.md)を参照。
