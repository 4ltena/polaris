# 本文量を維持したキャッシュ再利用と品質検証

v0.10.0 Algediの追加検証。本文・履歴・tool定義を増減させず、同一ユーザーターン内の通信情報を引き継ぐ任意設定`POLARIS_TURN_AFFINITY=on`を実装・測定した。全52試行・192ユーザーターンは品質検査に合格したが、層別・課題別のトークン量の基準を満たさなかった。既定は`off`を維持し、性能改善を理由とした既定化は行わない。

## 変更と条件

Codex providerが正常に完了した応答の`x-codex-turn-state`をメモリ内で保持し、同じターンのtool継続要求へ再送する。次のユーザー入力、子agent、宛先・アカウント・モデル・推論強度・cache keyの変更へは持ち越さない。成功したcompaction後にも破棄する。生値は保存・診断ログに含めない。

同じ要求のoff/onで、送信するJSON本文のバイト列が一致することをmockで検査する。[公式キャッシュ仕様](https://developers.openai.com/api/docs/guides/prompt-caching)にあるように、prefix一致だけでhitが保証されるわけではない。ヘッダー伝播による改善は別途実測する。

モデルは`gpt-6-astra`、推論強度は`medium`、固定文は`compact`。新規の固定文追加や要約強化は行わない。以前の固定文追加の比較は[別の結果](gpt6-cache-cost-results.md)を参照。

例示数0・1・3はzero-shot・one-shot・few-shot。短期9ケースは任意2軸の値の組を網羅するが、3軸の全27組ではない。skillは必要時に検索するため、tool0でのskill数差は常時本文量が変わらないことの対照となる。

長期ケースでは古い値の想起、訂正後の値、Unicode、複数事実の照合、skillの検索と本文取得、資料更新後の再読込を確認する。JSONの型・キー・値だけでなく、当該ターンに成功したtoolの引数と順序も検査する。モデルには課題に必要な資料・会話だけを送り、採点用の正答オブジェクトは送らない。

## 判定と限界

全品質・scope・使用量検査に合格し、各層の総入力＋出力が対照の95〜105%内、個別ケースの増加10%以内であることを採用条件とする。キャッシュ率、非キャッシュ入力、API換算費用も確認する。生成のばらつきをトークン追加・削除で補正しない。

既存の5課題を各条件3回、追加で30試行測定した。初回の10試行を含む値で、品質行列22試行と合わせて52試行となる。初回と3巡目はoff先行、2巡目はon先行。品質行列ではケース間で先行条件を交替した。同じバイナリと課題を使い、プロセスごとのcache namespaceは新しくした。

|---|---:|---:|---:|---:|---:|---:|---:|
|修正・根拠選択 off|15|72,419|5,292|5,888|77,711|8.13%|$0.935798|
|修正・根拠選択 on|15|67,861|5,433|2,048|73,294|3.02%|$0.931828|

全体ではキャッシュ率が0.59ポイント上がり、非キャッシュ入力は2.98%、標準API換算費用は1.81%減った。しかし修正・根拠選択層の総量は5.68%減で、95〜105%の量維持条件を外れた。また複数ファイル修正は17,430から20,018トークンへ14.85%増え、課題別の増加10%以内という条件も満たさなかった。全体の値でこれらを相殺せず、不採用とした。

送信JSONの同一性は回帰テストで確認しており、実測の総量差は生成内容・要求数の差を含む。今回の比較だけで差の因果関係や再現性は断定できない。ヘッダーはon側168要求のうち72要求で送信され、機構自体の動作と性能の改善を分けて確認した。off側は171要求で送信0回だった。

全339モデル要求の使用量・モデル・推論強度を照合し、失敗・欠測・再試行・cache write・embedding要求は0。実測全体は498,071トークン、標準API換算$3.469934。料金換算は[既存の計算法](gpt6-cache-cost-results.md#料金と計算方法)を使い、実請求やCodexの利用枠と区別する。キャッシュ入力は入力の内数であり、総トークンへ再加算しない。

## 回帰検証と再現性

`cargo test --locked --offline --workspace`は952件、品質driverのexampleテストは6件、Python検査は38件成功した。`cargo fmt --all -- --check`と`cargo clippy --locked --offline --workspace --all-targets -- -D warnings`も成功。同一要求のoff/onでJSON本文のバイト列が一致し、正常なSSE完了後だけ状態を保存すること、宛先・認証主体などが変わると破棄すること、並行context間で共有しないことを検査した。

測定前にRustソース・実行ファイル・driver・課題・実測スクリプトのSHA256を固定した。製品バイナリは`8c9e14c4c39a27e94c93e389cf65ae98bfbdc81db1ddba54270d18e6ac13df14`。保存済みの52試行を同じ検査器で再評価し、実測のやり直しや不合格行の除外は行っていない。独立レビュー後に集計の照合を強化し、旧版・新版のhashを保存した。課題、正答条件、モデルへ送った内容は変えていない。

合成課題の合格は製品全般の精度保証ではない。新しいdriverは製品と同じSession・agent::run・providerを利用するが、CLIの起動処理を完全に再現するものではない。GUI、実MCP接続、web search、自動要約ベクトル化は今回の実測対象外。認証・分岐・compaction・並行contextの境界はオフライン回帰と区別して報告する。
