# GPT-6のキャッシュ率と費用の比較

2026-09-07。v0.10.0 Algediの開発中に、総トークン数の最小化から、品質を保った標準API換算費用の最小化へ評価軸を変更した。ChatGPT認証経路の使用量に公開API単価を当てはめる比較であり、実請求額やCodexの利用枠消費量ではない。この実験ではstableを既定採用せず、v0.10.0もcompactを維持する。

## 比較設定

同じバイナリ、`gpt-6-astra`、推論強度`medium`、`--tool-memory retrieval`で、次の2設定を比較する。

|設定|動作|
|---|---|
|`POLARIS_CACHE_PREFIX=compact`|従来の指示文と送信形式。未指定時も同じ。|
|`POLARIS_CACHE_PREFIX=stable`|固定ガイド621参照トークンを指示文の先頭へ追加する任意設定。|

stableは正確に`gpt-6-astra`を指定し、toolsが空でない要求だけに適用する。要約などのtool-less要求には追加しない。本文・ツール順・call ID・権限は保持する。固定文を反映してから既存のキャッシュキーを生成し、profile・版・内容の指紋・適用有無はローカルの要求別ログに記録する。診断用の追加APIパラメーターは送らない。不正なprofile値はHTTP要求前に拒否する。

固定文は`stable-v1`、FNV-1a識別子は`08e69fd1dbfb7678`。空白の水増しや課題の正答は含めず、探索・契約保持・検証・報告の一般的な手順を記載する。参照トークナイザーはo200k_base。事前測定の単一ファイル修正用fixtureで再構成したinstructions/toolsのJSONはcompactが742、stableが1,383参照トークンだった。後者の6,969バイトは要求別ログのprefix長と一致する。JSONの計数方法とサーバー内部の計数は異なるため、返却された入力トークン数と同一視しない。

既存の`prompt_cache_options`はChatGPT認証経路でHTTP 400となるため、`POLARIS_CACHE_MODE`は未指定とする。TTL・明示キャッシュ境界・通信先・認証方式は変更しない。

## 料金と計算方法

2026-09-07に確認した[GPT-6 Astraの標準API単価](https://developers.openai.com/api/docs/models/gpt-6-astra)は次のとおり。

|種別|100万トークン当たり|
|---|---:|
|通常入力|$10|
|キャッシュ読込み|$1|
|キャッシュ書込み|$12.50|
|出力|$50|

Iをキャッシュ込み入力、Cを読込み、Wを書込み、Oを出力とし、通常長の換算額を`[10*(I-C-W)+C+12.5*W+50*O]/1e6`とする。入力272,000超の要求は入力側を2倍、出力を1.5倍にする。要求ごとに計算し、全体の入力合計へ長文倍率を適用しない。

`scripts/benchmark_costs.py`はDecimalで計算する。書込み欠測、負数、非整数、入力とキャッシュの矛盾、totalの不整合、モデル・推論設定の相違、失敗要求、壊れたJSONL、空ファイルを完全な費用比較にしない。同じファイルの重複指定を拒否する。失敗要求の判明済み使用量は別に残す。

[Codexのクレジット表](https://learn.chatgpt.com/docs/pricing)の入力250・キャッシュ25・出力1,250を用いた参考計算も分けて出力する。別料金が確認できていないcache writeが正数なら、この参考値は算定不可とする。[Prompt cachingの仕様](https://developers.openai.com/api/docs/guides/prompt-caching)ではキャッシュもAPIのTPMに数えられる。API価格、APIレート制限、Codexプラン内の利用枠は別の指標として扱う。

stableの費用増$0.312626は、通常入力分$0.237860、cache read分$0.028416、出力分$0.046350に分解できる。各試行内のprefixとcache keyは全30試行で一定だった。可視履歴の書換えも観測されていないが、暗号化reasoningを含むサーバー内部の状態までは検査できない。固定部分の一致や長さだけでキャッシュ利用を保証できるとは結論しない。

### 判定器の補正と消費量の扱い

実行順はcompact→stable、stable→compact、compact→stable。各試行は新規fixture、最大12ターン。6試行目のstableでdivmod・2変数への代入、16試行目のcompactで剰余演算%が既存判定器の未対応構文となった。モデルは正常終了していたため、数値構文だけを限定追加し、全34試行を同じv3判定器で再評価した。

正答条件・fixture・依頼文・バイナリは不変。スクリプトのAST差分は判定器クラス内だけと確認した。元の未評価結果2件、旧スクリプト、各版のhashを保存し、モデル要求を繰り返さず未実行分のみを再開した。比較用の派生行には元の判定と再評価結果を併記している。一般のPython実行・import・文字列書式演算は追加許可しない。

本比較30試行は209,587トークン、標準API換算$2.215446。別枠の事前4試行30,103トークン・$0.297350を含む、この測定群全34試行は239,690トークン・$2.512796だった。事前結果は本比較へ合算せず、費用台帳には残す。提供元の一時障害用に確保した追加再試行1回は使用していない。

## 採用判断と次に検討する範囲

stableは任意の実験設定として残し、既定化しない。今回のような短い単発課題では、キャッシュを狙って固定文を増やす手法を採用しない。品質と費用の目標を両立できたとは報告しない。

次の候補は固定文の追加ではなく、既存の要求数と高価な出力の削減、実際の長期対話での履歴維持と再利用を対象にする。今回、各試行のprefixとキーは既に安定していたため、それだけの再修正を有効な改善と見なさない。待機時間やキャッシュTTLの変更で改善すると推測して実装せず、対応するbackendの根拠と別の比較仕様を先に用意する。今回の試行数を増やした後付けの候補選別は行っていない。

## 証跡と範囲

測定バイナリのSHA256は`ccec61859396cbb23009c83af6339ebca153c16d6174390ef2e539784214a2db`。モデル呼出しは共通の隔離ランナーで行い、指定fixtureだけを書込み可能にした。認証は読取り専用、通信先はchatgpt.comとauth.openai.com。ツールを実行する別sandboxの通信は禁止した。

生の証跡は開発者のローカル環境に保管しており、公開配布していない。`measurement-plan.json`、ソース・スクリプト・バイナリのhash、manifest、回答、fixture、監査ログ、要求別使用量を保存する。`screen-summary.json`と`screen-verified-rows.json`は再検証済み。

これは単発の合成課題での比較であり、長期対話、通常Codexとの比較、保存済み対話の自動意味検索は対象外。次のv0.11.0では、直近10ユーザーターンを残し、それより前の対話を要約文からベクトル化する方式を検討する。今版ではその自動化を実装していない。
