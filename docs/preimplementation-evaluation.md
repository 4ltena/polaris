v0.11.0では、コード修正だけでなく企画・仕様・実装計画の品質を評価する。各ケースは初回回答と条件変更後の回答の2ターンで、制約や根拠を引き継ぎながら案を修正できるか確認する。

| ID | 段階 | 評価する内容 |
| --- | --- | --- |
| PRE01 | 課題整理 | 事実と未確定事項を分け、追加情報だけを確定事項へ移す |
| PRE02 | 企画 | 制約に合う複数案を示し、利用できない手段を候補から外す |

| PRE05 | 受入条件 | 正常系・異常系・境界値を要件と対応づける |
| PRE06 | データ設計 | 関係・制約・同時更新を検討し、二重貸出を防ぐ |
| PRE07 | 実装計画 | 依存関係・移行・検証を順序づけ、バックアップを前提に加える |
| PRE08 | 計画レビュー | 未解決の欠陥を指摘し、修正済みの問題を繰り返し指摘しない |

実装計画は既存の`specify`段階に含める。新しい段階や権限は追加しない。比較は同じcandidateの追加機能なしとworkflow有効で行い、要求モデルはgpt-6-astra、推論強度mediumとする。分類対象skill・tool・例示数は0とし、workflow有効側だけに共通・段階別の必須skillを読み込む。既存のskill数・tool数・例示数の行列や長期対話試験は別に維持する。

JSONの形やキーワードの出現だけでは品質合格にしない。固定した事実、訂正、依存関係、要件と試験の対応を客観検査し、案の妥当性・具体性・根拠・漏れは条件名を伏せた回答レビューで評価する。未レビューや欠測を合格として集計しない。

8ケース・16入力と客観判定器を追加し、ローカルの正常・異常系検査を通した。実モデルの測定枠は8ケース×2条件×3反復×2ターンで最大96要求として承認済み。入力・バイナリを固定し、使用量を記録して実行する。完了するまで、この数を実施済み件数として扱わない。
