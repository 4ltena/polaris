常時コンテキストは、実際に送信されるシステムプロンプトとツールスキーマを `tiktoken_rs::o200k_base()` で数えた実測値である。見積ではない。

この表の数値は実装者の実測で二度訂正されている。以前ここに書かれていた「176 トークン」と「23 件」は、どのテストも測っていない値だった。数値を書くときは、それを産んだテスト名を添えること。下限は `budget.rs` の `always_on_context_stays_within_budget`、最悪ケースは `constitution.rs` の `full_always_on_context_stays_within_budget` が測っている。

## 決めたこと

- subagent の契約は型定義へ畳み込み、呼び出しは 60 バイト程度に収める。現行 orchestia の 1 体あたり約 2,900 バイトに対して 98 パーセントの削減
- 常時コンテキストは skill 数から独立させる。発見はローカルのルータが担い、skill 名の一覧を常時載せない
- ルータは加算のみで、憲法ブロック、ツール定義、サンドボックス方針、承認境界には触れられない
- 選ばれた skill はメッセージ末尾へ差し込む。接頭辞を動かさないことでプロンプトキャッシュを維持する
- 監査ログに署名は付けない。インプロセスでは署名する主体と行為する主体が同一であり、ログ以上のことを証明しない
- subagent は深さ 1 で固定し、動的な分割は継続波で扱う
- サンドボックスは自作せず、macOS の `sandbox-exec` と Linux の landlock へ委譲する

裁定の全文は台帳の `Ruling:` 行にある。

## 繰り延べた指摘

最終レビューで判断する。

- 憲法の見出しフォールバックが `## ` でしか止まらず、`# ` や `---` で次節が始まる AGENTS.md では EOF まで拾う。予算は cap が守るが、内容は的外れになりうる
- `read_block` が権限エラーと不正 UTF-8 を「ファイル無し」と同じ空文字列に潰す。規則が無視されたことに気づけない
- `load_from` の両方存在ブランチが、結合後の文字列を再計測していない。誤差の向きは常に保守側で予算超過には至らない
- `already_capped_input_is_unchanged` が極端に短い入力しか通さず、防御 cap の有無で結果が変わらない
- `denies_case_variants` の `.SSH/id_rsa` が、ディレクトリ成分の小文字化を単独では固定していない
- `polaris-core` の `thiserror` が未使用。Task 10 の `AgentError` が消費する予定
